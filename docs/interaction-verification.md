# 返回、识屏、裁剪与提示词验收

## 首页与悬浮球 UI 更新

- 首页仅保留开始搜题及悬浮识屏开关；底部导航为首页、我的。
- 我的包含 API 设置、历史记录、收藏；子页面返回我的，搜题流程隐藏底部导航。
- 悬浮窗使用 52dp 触摸区域、约 48dp 半透明圆球和扫描符号。采用渐变与细颗粒模拟磨砂质感，当前没有启用跨窗口实时背景模糊。
- 未添加第三方依赖。浅色、深色配色统一，横屏使用紧凑首页，大字体可滚动。
- `work/verify_ui_refresh.sh` 已验证 API 36 模拟器：我的各入口、边缘返回、开关开/关、撤销悬浮权限后的状态同步、取消与再次授权、识屏进入裁剪、返回首页后关闭。
- `work/verify_ui_layouts.sh` 用于测试模拟器的深色、小屏、1.5 倍文字及横屏截图；只应在专用模拟器上运行。

## 自动检查

在项目根目录通过 Git Bash 运行 `bash work/run_logic_checks.sh`：覆盖宽图留白映射、选区平移、独立边调整、全图与单像素边界、10,000 次随机拖动、系统返回路径。

`bash work/verify_build.sh` 使用 Android Studio 已配置的本地 Gradle 和项目 JDK 17 构建 Debug、Release；日志在 `work/build-verification.log`。Release 产物未签名。

## Android 16 / vivo 验收步骤

1. 开启系统手势导航，依次进入设置、选图、裁剪、搜题、结果、历史详情。边缘返回应逐级返回；裁剪框内拖动不触发应用自定义返回手势。
2. 选取横图、竖图，分别拖动四边及四角，再将选区移到边界；确认保存后的内容与框内一致。全选不能导致图片被回收后黑屏。
3. 在搜题页修改提示词，进入结果后返回，内容应保留；重新选一张图片或识屏新题，内容应恢复默认。API 设置页不应再有提示词输入框。
4. 开启悬浮窗，允许悬浮窗权限；通知权限可选，但允许后可从通知启动识屏。切换到其他应用，点击悬浮按钮，先取消授权，按钮应恢复；再授权，截图应进入裁剪。
5. 逐一验证：连续截图、权限撤销、授权取消、锁屏中断、屏幕旋转、截图过程中返回。不得静默卡住或重复打开结果。
6. vivo 若拦截点击，请在系统应用权限管理中检查“后台弹出界面”“悬浮窗”和后台运行限制；菜单名称随 OriginOS 版本变化。可用通知里的“识屏”操作作备用入口。
7. 对禁止截图的安全页面，系统可能输出黑屏；应用不绕过系统保护。

## 本次实测（2026-11-03）

- Android 16 / API 36 Google APIs 模拟器：取消授权后重新授权、连续两次跨应用识屏、截图进入裁剪、右边独立拖动并保存均通过。
- 提示词编辑后返回裁剪再进入搜题、请求配置错误后返回搜题：文字保留；识屏新题：恢复默认。
- API 设置页无提示词输入框；系统返回键和真正的屏幕边缘滑动均可返回首页。
- 截图完成后 `dumpsys media_projection` 为 null；应用崩溃日志为空。
- Debug / Release 构建通过。Release 未签名；已有 Kapt / Gradle 弃用警告仍存在。
- 未接入真实 API，因此未验证实际模型答题；未连接 vivo 真机，也未完成拍照硬件和全部横屏/大字体组合验收。

模拟器流程脚本为 `work/verify_device_flow.sh`：仅用于已开启悬浮窗权限、通知权限的 1080×2400 API 36 测试模拟器，会停止并重启测试应用，不应直接用于存有个人数据的真机。脚本不会清除应用数据。

## 边界

构建通过不等于所有机型行为已验证。原生 Android 模拟器不能证明 OriginOS 后台策略已通过；vivo X100s Pro 必须按上述步骤复测。识屏每次都由用户发起并经过系统授权，不后台持续录屏。
